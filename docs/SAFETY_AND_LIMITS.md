# 安全、恢复与已知限制

## 支持范围

| 功能 | 范围与限制 |
|---|---|
| Block JSON 快照 | 保存 Block 结构；不包含媒体二进制、评论、协作者和分享权限 |
| 文本回滚计划 | 仅支持已验证的文本修改；不支持结构性增删、合并或表格结构恢复 |
| 本地目录约束 | 约束目录导入路径；原生工具不受同一路径限制 |
| 版本固定 | 源码提交由锁文件指定；npm 依赖由首次安装生成的锁文件固定 |
| 验证 | 离线测试、构建、SDK 集成和账号测试分别执行、记录 |
| 共享 Token | 两套服务使用同一授权用户的访问权限 |
| 数据传输 | 导入内容上传飞书，读取结果可由 MCP 客户端交给模型服务处理 |
| 写入恢复 | 本地与远端分别写入；失败时保留检查点，必要时人工核对 |

## 原生修改风险

`docs__feishu_update_document` 会删除并重建文档，无法保留原链接。调用前需同时启用 native writes 和 native destructive。原生 Block 工具使用上游实现，不经过计划层。

FeishuApi 不自动重试写请求，文档上游设置 `FEISHU_MAX_RETRIES=0`。原生复杂操作包含多个 API 步骤，可能部分成功；上游仍会执行临时导入文件清理。

融合模式下，Blocks 的 Token 失效/缺少授权路径不会再进入独立缓存或生成旧版授权链接，只提示使用 `kb_auth`。不要使用旧版 Blocks OAuth 链接；其中的 state 曾包含仅 Base64 编码的应用密钥。

## 导入失败的人工处理

`kb_inspect_plan({planId})` 查看：

- `job.items` 中的文件、状态、documentId、父节点、revision；
- `job.directories` 中可能成功创建但响应丢失的目录节点；
- `error` 和已完成的映射。

遇到 `needs_inspection`，同计划不再自动执行，同目的地的新导入也被阻止。不得通过改数据目录、删除计划来绕过这个保护。

导入包含创建云文档和移动到 Wiki 两个阶段。只有在指定父节点下找到对应 Docx 节点后才更新同步基线；否则保留 documentId 和 `needs_inspection`，不得重新上传。核对实际位置或等待移动结果明确后，再修复状态。

核对飞书结果后，调用 `kb_reconcile_import` 修复本地状态，该工具不修改飞书。

已实际创建但响应丢失：

```json
{
  "planId": "失败计划ID",
  "confirmed": true,
  "resolutions": [
    {"path": "AI/RAG.md", "outcome": "adopt", "document": "实际创建文档的URL或ID"}
  ]
}
```

接管时校验文档可读、位于记录的 Wiki 父节点，且未关联其他文件或旧版本。正文需人工核对，接管后标记为 `remoteEdited`。

人工确定这次没有创建文档：

```json
{
  "planId": "失败计划ID",
  "confirmed": true,
  "resolutions": [
    {"path": "AI/RAG.md", "outcome": "not_created"}
  ]
}
```

每个 `uploading/created` 项必须有一个 resolution。已返回 documentId 的项目不能声明 `not_created`；其余项目也需人工确认未创建后才能使用该结果。

部分目录创建失败而未开始任何文档上传时，resolution 可以为空数组；仍要人工检查目录结果。后续导入会按名称重新查询目录并拒绝同名歧义。

状态修复完成后标记 `closed_after_review`，再生成新的导入计划。不会自动重放整个旧任务。

## 文本修改失败

API 超时、写后读取失败或文字不一致时，计划进入 `needs_inspection`。先使用 `kb_read` 核对当前状态，再决定后续操作，禁止直接重发原计划。

写入确认必须包含有效的 `document_revision_id`，且与读回版本完全一致；文本修改还比较完整文本元素及行内样式（仅将未提供的布尔样式与显式 false 视为等价）。写后出现其他版本或样式不符时，不标记 applied，也不开放自动回滚。历史已完成计划若没有匹配的写入确认版本，同样拒绝自动回滚。

仅 `applied` 的文本计划可通过 `kb_plan_rollback` 生成逆向计划，且远端 revision 必须等于修改完成时的版本。反向计划也要再次审批；期间出现并发修改会拒绝执行。追加段落、结构性修改不提供自动完整回滚。

## 本地数据保护

`.local/oauth` 使用未加密的文件存储。POSIX 推荐根数据目录权限 700、状态文件权限 600；Windows 使用 ACL。凭据目录不应共享、提交 Git 或作为调试附件发送。

进程异常退出后可能留下 `.local/server.lock`。锁不会自动过期；确认对应 PID 已退出、没有客户端使用该数据目录后，才能人工删除。

媒体上传和远程媒体下载默认关闭。启用本地媒体时会检查路径，拒绝已检测到的目录外引用和遍历。检查器仅覆盖支持的引用语法，原生上传工具不受同一限制。

## 范围限制

- 高层工具支持 Feishu 中国站 Docx / Wiki URL；旧版 Docs、Sheets、Base 和国际 Lark URL 不在支持范围内。原生工具按上游能力提供。
- Markdown 导入的复杂语法、嵌套表格、图片、公式、画板等以真实飞书 API 和上游行为为准，需要用自己的测试集验证。
- `kb_plan_append` 只追加纯文本；`kb_plan_patch` 不把 Markdown 自动转换成复杂富文本。
- 辅助 Markdown 导出可能损失结构与样式；JSON 有完整读取到的 Blocks，但不包含媒体字节和所有协作元数据。
- 缓存搜索只查询已读取的本地快照，不主动扫描整个 Wiki，不提供语义检索或索引实时同步。
- 没有后台持续 watcher、自动双向同步、无人值守冲突合并、分布式锁或公网多用户认证。
- 单次安全文本更新或追加最多 50 个项目；文件大小默认 10 MiB；文档快照最多 100,000 Blocks。
- 原生工具按名称区分读写，具体行为以所属上游实现为准；原生写入默认关闭。

正式知识库迁移前，请用副本验证你实际采用的 Markdown、图片、表格和权限模型。
